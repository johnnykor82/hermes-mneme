# Hermes-Mneme

> 🇬🇧 Read in English: [README.md](README.md)

> Retrieval-based context engine для [Hermes Agent](https://github.com/NousResearch/hermes-agent) с постоянной памятью событий и retrieval, учитывающим граф исполнения.

**Mneme** (Μνήμη — древнегреческая муза памяти) — плагин context engine для Hermes. Он сохраняет полученные события диалога в SQLite, индексирует их для семантического и лексического поиска, связывает вызовы инструментов и выбирает контекст для запросов к модели в рамках заданного токен-бюджета. Это помогает находить старые детали, но найденные свидетельства нужно сверять с исходными событиями.

Mneme дополняет [Mnemosyne](https://github.com/johnnykor82/mnemosyne) — отдельный плагин Hermes для кросс-сессионной памяти.

## Возможности

- **SQLite event store** с детерминированными ID событий и идемпотентной обработкой повторов при возобновлении сессий и компрессии.
- **Индекс эмбеддингов** на [sqlite-vec](https://github.com/asg017/sqlite-vec) с Python-фоллбэком и настраиваемыми OpenAI-совместимыми провайдерами эмбеддингов.
- **Сегментация тем** по дрейфу эмбеддингов с дополнительными сигналами классификатора.
- **Классификация намерения** для сигналов продолжения, смены темы, новой задачи и уточнения; этот путь детерминированный и не вызывает LLM.
- **Граф исполнения**, связывающий вызовы инструментов, их результаты и решения для навигации по свидетельствам.
- **Опциональные reranking и обогащение состояния через LLM**, если они настроены.
- **Инструменты памяти:** `context_search`, `fetch_event`, `expand_context`, `get_execution_state`, `list_segments`, `get_goal_history` и `recall_recent`.
- **Наблюдаемость** через JSONL-трейсы по ходам и метрики в памяти.

## Установка

Этот README описывает релиз **v0.5.3**. Команда ниже переключает репозиторий на тег этого релиза; в ветке `main` могут быть более поздние, ещё не выпущенные изменения.

```bash
git clone --branch v0.5.3 --depth 1 https://github.com/johnnykor82/hermes-mneme.git \
  ~/.hermes/plugins/hermes-mneme
cd ~/.hermes/plugins/hermes-mneme
./install.sh
```

Если Hermes ещё не настроен на использование Mneme как context engine, укажите имя движка в `~/.hermes/config.yaml`:

```yaml
context:
  engine: hermes-mneme
```

После установки и настройки перезапустите Gateway:

```bash
hermes gateway restart
```

Установщик определяет виртуальное окружение Hermes (по умолчанию `~/.hermes/hermes-agent/venv`), устанавливает зависимости из `requirements.txt` и проверяет установку. Чтобы использовать другое окружение, задайте `HERMES_VENV`. Поддерживаются Python 3.10+, macOS и Linux.

Проверить активацию можно так:

```bash
tail -f ~/.hermes/logs/agent.log | grep -i mneme
```

## Конфигурация

Настройки применяются в таком порядке: встроенные значения → `config.yaml` → переменные окружения `HERMES_CTX_<KEY>` → явные параметры конструктора. Некорректные значения игнорируются с диагностическим сообщением. См. [справочник настроек](docs/configuration.md) и полную схему в [`config.py`](config.py).

Основные настройки:

- `active_window_tokens` и `context_window_usage_percent` задают бюджет контекста
- `protected_tail_turns`, `state_budget_ratio` и `retrieved_budget_ratio` управляют сборкой промпта
- `dependency_max_depth` и `dependency_decay` задают обход графа
- `reranker_enabled` и `reranker_endpoint` включают второй этап ранжирования
- `llm_enrichment_enabled` включает дополнительное обогащение состояния
- `segmentation_enabled` и `drift_threshold` управляют обнаружением границ тем
- `embedding_endpoint`, `embedding_model` и `embedding_dim` задают сервис эмбеддингов; модель и размерность должны совпадать

Встроенный порог дрейфа — `0.35`. Это настраиваемое рабочее значение, а не универсальная оценка точности и не порог, откалиброванный на размеченном русско-английском наборе данных. При использовании только эмбеддингов сравнивается нормализованный дрейф `(1 - cosine_similarity) / 2`; при наличии могут учитываться дополнительные сигналы классификатора.

## Поиск и проверка свидетельств

Релиз v0.5.3 основан на исправлениях ветки 0.5.x для жизненного цикла сессий, сегментов и состояния; корректной области поиска; и обработке повторов при возобновлении и компрессии. В v0.5.3 добавлены гибридный поиск памяти, фрагменты с метаданными источников, исключение текущего хода и более безопасное расширение сегментов.

По умолчанию `context_search` ищет в активной теме и сессии. Укажите `segment='all'`, чтобы искать по всем темам текущей сессии; для явного кросс-сессионного поиска задайте `segment='all', session='all'`.

Инструмент поиска памяти объединяет семантических и BM25-кандидатов с помощью reciprocal rank fusion, а затем ранжирует ограниченный пул кандидатов, если настроен reranker. Эта гибридная схема относится к инструменту поиска памяти и не заменяет политику автоматического извлечения контекста в prompt router. Результаты содержат ограниченные релевантные запросу фрагменты, роль источника, сессию, сегмент и признак усечения. При необходимости используйте `fetch_event`, чтобы прочитать исходное событие. Результат ранжирования — свидетельство для проверки, а не доказательство того, что утверждение было принято или выполнено.

Если доступны оба нативных хука Hermes — `select_context()` и `on_turn_complete()`, Mneme использует их. Выбор контекста меняет исходящий запрос к модели; завершённые ходы отдельно записываются в память, а выбранный контекст не добавляется в сохранённую стенограмму. Gateway Hygiene остаётся независимой функцией хоста Hermes и может отдельно сокращать сохранённую историю при настроенном пороге (по умолчанию 85%); Mneme не отключает и не контролирует её. На старых версиях хоста используется прежний путь через `compress()`. Исключения текущего хода в нативном режиме сохраняются через синтетические продолжения.

`expand_context(mode='segment')` возвращает ограниченный каркас сегмента и сообщает, если он неполный; по отсутствию факта в каркасе нельзя заключить, что его не было в истории. Для общего старого ID сегмента может потребоваться seed event, чтобы определить исходную сессию. При поиске свидетельств продолжайте работу полезными расширенными или альтернативными запросами, просматривайте соседние события и при необходимости загружайте оригиналы. Жёсткого лимита попыток поиска нет, и отсутствие в одном top-k результате не доказывает отсутствие сведений в памяти. Подробнее — в [описании retrieval](docs/memory-retrieval.md).

Индекс FTS для лексического поиска — производные данные; он атомарно строится при первом использовании. Первичная сборка добавляет задержку и расход диска, но не переписывает исторические события и не выполняет автоматическую миграцию старых ID сегментов. Перед первым построением индекса на большой существующей базе следуйте безопасной процедуре из [руководства по retrieval](docs/memory-retrieval.md): остановите процессы, записывающие в базу, создайте SQLite-бэкап через backup API с учётом WAL, инициализируйте индекс и проверьте целостность до перезапуска. Отдельное [руководство по миграции старых сегментов](docs/audit-migration.md) описывает явную миграцию с бэкапом.

При превышении оценённого бюджета промпта возникает `PromptBudgetExceeded` с оценкой `actual_tokens` и настроенным `budget_tokens`. Оценка использует выбранный токенизатор. Текущий хост Hermes перехватывает ошибки hook и может вернуться к исходному запросу, поэтому Mneme не гарантирует строгое соблюдение лимита на стороне провайдера.

При проверке исторических свидетельств отличайте слова пользователя от просьбы или завершённого действия: сообщение пользователя подтверждает, что он сказал; сообщение ассистента может быть предложением; вызов инструмента фиксирует попытку действия. Перед тем как назвать результат завершённым, проверьте соответствующий вывод инструмента или исходное событие.

## Архитектура

Описание компонентов находится в [`docs/`](docs/):

- `store.py` — SQLite-хранилище событий и lineage сессий
- `index.py` — семантический и лексический индексы
- `segmenter.py` — сегментация тем по дрейфу
- `classifier.py` — детерминированные сигналы намерения
- `router.py` — автоматическое извлечение контекста и ранжирование
- `prompt_builder.py` — сборка промпта в рамках токен-бюджета
- `engine.py` — жизненный цикл, нативные хуки и резервный путь через компрессию
- `graph.py` — граф исполнения и обход зависимостей
- `tools.py` — инструменты памяти агента

## Обновление

Перед обновлением работающей установки дождитесь завершения ходов Gateway и остановите Gateway и остальные процессы, записывающие в базу. Создайте бэкапы базы Mneme и Hermes `state.db` через SQLite backup API с учётом WAL, сохраните конфигурационные файлы Hermes и плагина. Затем загрузите теги и переключитесь на нужный тег релиза (Git перейдёт в detached HEAD), запустите установщик и перезапустите Gateway:

```bash
cd ~/.hermes/plugins/hermes-mneme
git fetch --tags
git checkout v0.5.3
./install.sh
hermes gateway restart
```

Используйте тег выпущенной версии; в `main` могут быть ещё не выпущенные изменения. При первом построении FTS-индекса на большой существующей базе выполните также предварительную сборку и проверки целостности из [описания retrieval](docs/memory-retrieval.md).
