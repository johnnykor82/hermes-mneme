# Independent audit verification and remediation

Base: `6de064f134715c4f3c1a594460c98cc3e3d64db6` (published and installed 0.4.0). Release: 0.5.0. Audit date: 2026-10-10. Verification used Python 3.11 with sqlite-vec and deterministic offline fixtures. Gateway configuration is unchanged.

## Independent results

The original suite passed **61 tests** on the baseline. Running the captured non-migration regression cases against a separate archived `6de064f` tree produced **60 failures and 3 passes**. The baseline harness aliases the new, absent overflow exception to ValueError solely to allow collection; source implementation is unmodified. Migration is new functionality (its first test run failed because the module did not exist). Individual red/green evidence is described in the component reports. All fixes use temporary DBs and deterministic vectors/mocked HTTP. Final local suites passed **134 tests**, both standalone and against the native Hermes ContextEngine ABI; bytecode compilation and `git diff --check` passed. Cross-platform CI results are recorded by GitHub on the release PR.

## Migration validation

Read-only dry-run, SQLite backup API, transactional migration and repeat no-op were verified on temporary fixtures and an isolated database copy. Protected event/embedding/graph/state digests and counts remained unchanged; integrity and orphan checks passed. The migration creates lookup indexes before updates. Detailed operational counts and timing from the private database are retained locally and are not included in this public report.

The public regression fixture contains 441 synthetic sessions. It exercises separate legacy segment naming, collision handling, metadata/state scope, idempotence, rollback, WAL backup and actual vec0 reopen. See the migration guide for commands and rollback. No live migration runs automatically at startup.

## Performance evidence

The 100k-vector results are in the index report. A second reproducible run with `scripts/benchmark_audit.py --rows 1000000 --samples 5` used one million 1024-dimensional vectors, 1000 sessions, 1000 vectors/session, top_k=5, no HTTP. Setup took 16.005 s. These synthetic results are diagnostic, not production SLAs.

| Operation | Median | Worst of five |
|---|---:|---:|
| Scoped exact sqlite-vec search | 4.853 ms | 17.958 ms |
| Global exact sqlite-vec search | 9420.809 ms | 9802.446 ms |
| Cached centroid | 0.008 ms | 0.048 ms |

First centroid load took 16.625 ms. Five samples are insufficient for meaningful p95/p99 service guarantees; sample quantiles in the script are order statistics only. Unlimited global retrieval remains potentially expensive and memory grows with returned matches; finite top_k limits results without silently changing documented unlimited semantics.

No real endpoint calls, semantic resegmentation, auto historical data deletion, model context-window calibration, or attribution of the reported 14.59s incident is claimed. Provider tokenization can differ from configured estimate. These explicit exclusions are part of the release scope rather than silently treating all acceptance rows as measured.

The first macOS CI run exposed a Python build without SQLite extension-loading support. Plain database migration now avoids requiring an unused extension API; vec0 databases produce an explicit runtime requirement. CI uses pinned uv managed Python and an sqlite-vec load preflight on every platform/version so extension tests cannot silently disappear.
